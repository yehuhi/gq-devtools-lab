Important QA principle

Use scripts to create Preconditions, not to skip the feature you are actually testing.
If your test is âCreate Policyâ, test creation through the UI. If your test is âCancel an active policyâ, creating the active policy through Console/API can save time because creation is only setup.

QA Utility Functions â 12 exercises

Start from the real UI request, build a working function with fixed values, then improve it step by step into a reusable QA helper.

QF1Create Customer Function â Fixed Values

Create a customer through the UI, Copy POST /api/customers as fetch, verify it in Console, then wrap it as createCustomer() using the same fixed values from the request.

QF2Make createCustomer() Dynamic

Take your working createCustomer() and replace fixed firstName and lastName values with parameters. Keep the email unique on every run.

QF3Create Policy Function â Fixed Values

Create a policy through the UI, Copy POST /api/policies as fetch, verify it, then build createPolicy() with the fixed values from that request.

QF4Make createPolicy() Dynamic

Modify createPolicy() so firstName and coverageType are parameters instead of hard-coded values.

QF5Add Default Values

Improve createPolicy(firstName, coverageType) so createPolicy() also works with no arguments by using sensible default values.

QF6Create Claim Function

Submit a claim through the UI, inspect POST /api/claims, build createClaim() first, then make policyId, claimType and amount parameters.

QF7Create Payment Function

Record one payment through the UI, build createPayment() from POST /api/payments, then replace fixed policyId and amount values with parameters.

QF8Update Policy Function

Update a policy through the UI, Copy the PATCH request, build updatePolicy(), then make id and premium parameters.

QF9Cancel + Get Policy Functions

Build cancelPolicy(id) from the cancellation request and getPolicy(id) from GET /api/policies/:id. Use GET to verify the new status.

QF10Create Multiple Records

Use your parameterized createCustomer() or createPolicy() inside createCustomers(amount) or createPolicies(amount) to generate bulk test data.

QF11Create a Precondition Helper

Combine existing helpers into createCancelledPolicy(): create an ACTIVE policy, cancel it, return the resulting record, then continue the actual test manually in the UI.

QF12Upgrade the QA Snippet Toolkit

Save the final parameterized versions of your functions in a Chrome DevTools Snippet named âGQ QA Toolkitâ. After refresh, run the Snippet and call the helpers with different parameter values.
